# Guide format

Use the feature's product name as the title. Follow it with one sentence explaining what it does for the reader. Put any essential prerequisites before the steps, using a short paragraph or a `Before you start` heading when there are several.

Use the headings that fit the real flow. `Turn it on` works for setup, `Use it` for everyday actions, and `Try it now` for a quick check. Combine sections when the same steps accomplish both jobs. Add `If you get stuck` for actionable fixes to likely problems. Add `Turn it off` when the way back or its consequences need explaining. Put a short result sentence directly after the steps it describes.

Prefer short paragraphs and lists that are easy to scan beside the app. Use a screenshot only if it helps the reader find a control or recognize a result. Keep the steps usable as text.

## Example

This fictional example shows one way to present the guide. Use the actual feature's labels, roles, and behavior in a real guide.

```markdown
# Weekly digest

Get one email each Monday with activity from the previous week.

You need to be a workspace admin to turn it on.

## Turn it on

1. Open **Settings → Notifications**.
2. Turn on **Weekly digest**.

## Try it now

Select **Send preview**. Look for a sample digest in your account email.

## If you get stuck

- **Can't find Weekly digest?** Check that you're in the right workspace and signed in as an admin.
- **No preview email?** Check your spam folder and confirm your account email.

To stop future digests, turn off **Weekly digest** in the same settings.
```
