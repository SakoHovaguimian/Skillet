# Brand direction

Read this when creating or changing identity, imagery, or visual direction. Apply it within the selected modules; it does not add deliverables or authorize a rebrand.

## Turn the brief into design decisions

Establish the audience, product action, promise, context of use, and any fixed assets. Separate supplied facts from proposed positioning. Prefer a short, specific premise over a list of adjectives: for example, “Help independent repair shops see what needs attention next.”

Translate that premise into choices the reader can see:

| Decision | Evidence and visible consequence |
| --- | --- |
| Mark | Reuse the supplied mark, or connect a new mark to a meaningful action, initial, or idea. Explain the actual shape briefly. |
| Typography | Choose hierarchy, weight, width, and rhythm for the audience and reading tasks. Demonstrate real product language. |
| Color | Assign brand, surface, text, action, and status roles. Repeat those roles across applications. |
| Composition | Use scale, alignment, density, and spacing to establish the intended emphasis. |
| Imagery | Choose subjects, crops, materials, and treatments that support the product and repeat coherently. |
| Applications | Show the identity in the places this audience will encounter it. |

An organizing metaphor is optional. A clear typographic system may express the brand better than a symbol. When a metaphor helps, carry it through a few meaningful decisions rather than adding it to every surface. Avoid automatic mappings such as security → shield, AI → spark, or developer tool → black terminal. Category cues need justification from this brief.

References can inform density, scale, rhythm, image treatment, or color relationships. Use the requested aspects without copying another brand's distinctive mark, slogan, or unique asset. “Premium” alone does not decide a font, palette, or layout.

## Keep the identity consistent

Preserve supplied marks, proportions, colors, and usage rules unless redesign is in scope. Inspect each asset before using it. If only a raster logo is supplied, retain that asset; do not claim an approximate trace is its editable vector master. Request a missing essential variant or choose a compatible background before changing the logo.

For an authorized new mark, explore a small number of meaningful approaches internally, then develop a coherent direction. Useful approaches include a custom wordmark, initial plus product action, negative space, or modular geometry. Combine concepts only while the result stays legible. Do not invent research, symbolism, or construction measurements to justify a shape after the fact. Show a construction diagram only when it reflects how the mark was actually made.

Define one canonical logo source and reuse it across the guide. For inline SVG, use a shared symbol or equivalent reusable definition with a stable `viewBox`; give instances appropriate accessible names and unique title IDs. Treat wordmark, compact mark, monochrome, and reversed versions as deliberate variants of that source, not fresh drawings in each panel. New decorative icons must not be mistaken for alternate logos.

Inspect the mark at its smallest intended use, in monochrome, and against relevant light/dark backgrounds. Check silhouette, negative spaces, line weight, clipping, and clear space. Keep an existing brand's official variants intact; explain unsupported uses instead of manufacturing an unauthorized variant. Distinctive appearance is a design aim, not evidence of trademark availability.

## Build a usable visual system

Choose type roles the content needs. A monospace role is useful for code or tokens; an identity-only guide need not invent one. Use readable specimens and suitable fallbacks. Identify proposed font choices and any loading or bundling dependencies.

Use a disciplined palette with explicit semantic roles. Preserve exact brand swatches while adapting UI foregrounds and backgrounds for readable contrast. Status must remain understandable through text, shape, or icons as well as color. Check actual foreground/background pairs; do not claim measured contrast without measuring it.

Choose a consistent imagery language: subject, crop, viewpoint, light, texture, and palette relationships. Add grain, halftone, glow, or construction lines only when they serve this identity. Finish requested artwork with the permitted tools. Use sparse text in image-led brand presentations and readable explanations in guidelines and technical sections.

## Show the system in context

Compose the HTML as a reading sequence with varied emphasis: a clear introduction, a focused identity specimen, practical usage, and relevant applications. Mix calm and dense sections according to their content. Choose a responsive layout that supports the material; a fixed 3 × 3 board is not a requirement.

Use applications that demonstrate a decision: a small app mark, a product header, a meaningful label, a campaign treatment, or stationery when the product calls for it. Reuse the canonical mark, type, and palette across each. Physical objects, device frames, and elaborate mockups are optional.

Label static identity applications as illustrative mockups. They may show a product surface without promising its features or interactions. Keep them visually and semantically distinct from selected working product previews. Do not use inert interactive HTML controls in a mockup that looks operable.

## Review the result

- Trace the major visual choices to the brief or a clearly stated proposal.
- Compare every logo instance with the canonical source and intended variant.
- Inspect small-size legibility, relevant backgrounds, type hierarchy, and actual color pairs.
- Check that applications share a system while varying composition to suit their content.
- Remove unrelated decoration, invented product claims, unreadable labels, and unsupported claims of originality or commercial effectiveness.
- Inspect the narrow layout and asset fallbacks. Record any unperformed visual or contrast checks precisely.
