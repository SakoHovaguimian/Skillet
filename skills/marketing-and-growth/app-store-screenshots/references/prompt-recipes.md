# Generation and edit briefs

Use these fields to construct prompts for the available image tool. They are prompt ingredients, not literal API parameters. Follow the tool's current supported reference, size, editing, transparency, and output rules.

## Assign reference roles

Label each input's role explicitly:

- Edit target: the existing panel whose requested properties may change.
- Product evidence: the authentic capture supplying actual interface content.
- Brand source: the exact mark, palette, or identity to preserve.
- Style reference: composition or visual treatment only.
- Supporting photo: the image and identity constraints supplied by the user.

Do not let a competitor reference donate its logo or UI. Do not let an anchor panel's regenerated UI replace the original product capture. If a named reference has not been inspected or is inaccessible, say so and exclude it from unsupported fidelity claims.

## Anchor panel recipe

Specify, in this order when useful:

1. Deliverable and mode: one complete panel, intended aspect ratio/device, concept or controlled production asset.
2. Audience and one benefit, with the product evidence that supports it.
3. Exact headline, punctuation, and intended line breaks; optional support text and allowed copy variations.
4. Composition: focal point, image/capture area, relative scale, clear space for type, and crop limits.
5. Visual system: supplied colors, type character, background, device/frame treatment, and motif.
6. Reference roles and protected elements, including identity, product content, and any unchanged text.
7. Specific exclusions derived from the brief: unsupported badges, invented controls, extra phones, or unwanted human imagery, when relevant.

Ask for an individual finished panel, not a collage containing the whole campaign. If generating only a background or illustration for controlled assembly, explicitly request that asset without invented UI or lettering and preserve the intended capture/text area.

## Follow-on panel recipe

Reuse the accepted visual system and anchor as a style reference. Supply the new panel's one benefit, exact copy, original product capture, composition difference, and any edge contract. Keep those decisions explicit rather than asking for “another one like this.”

## Revision recipe

Name the edit target and the concrete defect or requested change. Specify the elements that must remain stable, and include original source assets when fidelity matters. For example, a headline correction should not also change the product values, logo, device scale, or background direction.

After an edit, inspect both the requested change and protected content. Image editing can alter nearby or unrelated details. Keep the prior accepted version until the revised output has been checked.

## Text and capture limitations

Exact text in a prompt is not proof of accurate rendering. Inspect the rendered glyphs, punctuation, line breaks, and any non-Latin script. Prefer a permitted controlled text layer for production when generative lettering repeatedly fails.

A prompt to “preserve every UI pixel” does not establish fidelity. The submission path requires an actual content-preserving composition method and inspection against the original capture. A generated full-panel concept remains a concept even when it resembles the capture closely.

Keep the successful prompt and reference-role mapping in the handoff. Record model/tool identifiers only when exposed by the environment. Do not invent seeds, deterministic reproducibility, or export dimensions the tool did not provide.
